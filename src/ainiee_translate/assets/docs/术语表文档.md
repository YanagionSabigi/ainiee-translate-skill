# 术语表：提取、审核与迁移

AiNiee 可以从当前文献与用户资料提取术语候选，整理上下文、页码和建议译法，再生成术语审核工作台供人逐项核对。工作台基于 [Review Workbench](https://github.com/YanagionSabigi/review-workbench)。用户可接受、保留、编辑或留言；保存草稿不会批准译名，提交本轮后回到聊天说“继续”，才核验并受控写回锁定表。机械校验不能替代对人物身份与词义的判断。

## Schema 与四类记录

正式文件是 `glossary.locked.json`，配套 `glossary.locked.schema.json`。根对象包含 `schema_version`、`taxonomy_version`、`categories` 和以下四类记录；领域由项目自己定义，不内置学科分类。新模组从空表开始。

| 类别／字段 | 必填内容 | 可选资料与处理 |
| --- | --- | --- |
| 人名 `persons` | 稳定 `person.*` ID、`source_form` | `chinese_translation` 保存音译或现成中文译名，`latin_form` 保存通行转写；`name_system` 为 `han`、`latin`、`other` 或 `unknown`。 |
| 术语 `terminology` | 稳定 `term.*` ID、`source_form` | `target_form` 为目标语言译法；或使用互斥的 `target_template`，通过 `references` 引用已存在的人名。 |
| 缩写 `abbreviations` | 稳定 `abbr.*` ID、`source_form`、`expansion`（展开义） | 可有 `target_form`、`keep_source`、`common`。同一缩写的不同义项分开建条，记录辨义说明。 |
| 禁翻 `non_translate` | `marker` | 可有 `regex`、`category`、`note`；用于占位符等保护规则，不充当缩写表。 |

人名、术语和缩写均可有 `note`（辨义或项目约定）、`category_ids`（领域）、`aliases`、`derived_forms`、`references`。领域集合 `categories` 使用稳定 `id`、`name` 和可选 `parent_id`、别名。禁止同姓就合并为同一人；同形多义项须用独立 ID 和 `note` 区分。

语言形式采用 `{"text": "…", "language": "…"}`。别名还有 `usage: accepted` 或 `recognition_only`，派生形式还有 `kind`。前者区分认可输出和仅供识别，后者说明派生关系。缺少依据的译法可以暂缺，但必须留待审核，不编造。

例如（以下是字段示意，使用时放入对应集合）：

```json
{
  "id": "term.n-tuple",
  "source_form": {"text": "n-tuple", "language": "en"},
  "target_form": {"text": "$n$-元组", "language": "zh"},
  "category_ids": ["algebra"],
  "note": "n 为参数，公式使用 TeX；领域 algebra 须在 categories 中定义。"
}
```

带公式的术语记录 TeX 格式，行内公式如 `$n$`、`$R$`；JSON 中的反斜杠需要转义，例如 `"$\\alpha$-稳定"`。公式不改成随意的 Unicode 近似字形，保留变量、上下标与原义。

## 译名与标点

正文的姓名模式默认 D，其中拉丁姓名保留源语言；术语表的目标译名栏仍填写音译或现成中文译名，不必再次抄写源文。人名使用 `chinese_translation`，术语使用 `target_form.text`；源文由 `source_form` 独立保存。正文的形式选择不会清空这些资料。

动态冠名可写 `target_template: "<<person:person.newton>> 定律"` 并在 `references` 列出该人名 ID；它会按当前姓名模式展开。动态模板与固定 `target_form` 二选一，不能把展开结果覆盖回正式模板。人名模板在中文姓名与汉字之间的空格须人工核对，记录项目约定。

译名及 `note` 遵循中英文加一个空格的约定；词内或同一姓名用 `-`，两位人名之间用 `–`，中文破折号用 `——`。例如 `Levi-Civita 联络` 中姓名内为连字符；`Newton–Leibniz 公式` 中两人之间为连接号。完整排印规则见[标点符号](标点符号.md)。识别用的源文保留真实写法。

## 整包迁移到其他项目

可以将术语表整个打包迁移到其他项目。打包前完成人工审核，检查同形词、身份、领域范围、固定译名与动态模板；将本表特有的转写、标点、公式或禁翻要求写入说明文件。

```text
python -m ainiee_translate.glossary lint --locked work/glossary.locked.json
python -m ainiee_translate.glossary_bundle --locked work/glossary.locked.json --out out/术语迁移包.zip --notes 本表特殊说明.md
```

ZIP 包含词表、词表 Schema、基础 Schema、`glossary.locked.policy.json`、政策 Schema、这份术语表文档、标点说明与 `本表说明.md`。本表说明自动记录模式、领域范围和带说明、引用、姓名体系或公式的特殊条目，并附上 `--notes` 提供的说明。未提供补充说明时会明确标注。已有 ZIP 不覆盖，坏的政策绑定会拒绝打包。

接收方完整解压，将词表、Schema 和政策放在新翻译模组中，先核对领域与译法再加载。`policy_sha256` 绑定政策的原始字节，移动时不得单独改名、改行尾或遗失配套政策；通过工具修改政策并重新绑定。模式可在新模组的 `预设参数.md` 中选择，重新加载后项目会获得新的绑定快照。修改姓名预设后，请先加载模组，再打包项目 `work` 下的快照；直接打包尚未同步的模组词表会拒绝，防止携带旧模式。

包内 Schema 自包含，解压后应同时用基础 Schema 与词表 Schema 校验。设置 `AINIEE_GLOSSARY_SCHEMA` 时保留该项目契约；否则优先使用词表旁的同名 Schema，再回退到内置 Schema。若同时存在两份不同的自定义契约，先合并成一份再打包，避免丢失约束。外部 `$ref`／`$dynamicRef` 依赖会拒绝打包，须先内联为自包含 Schema。旧 `characters/terms` 格式需先人工迁移再打包。术语迁移包不包含原书、译文缓存和审核决定；另有“给别人审核的包”用于传递审核任务，不能混为同一种用途。
