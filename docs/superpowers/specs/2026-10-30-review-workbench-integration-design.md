# AiNiee 校对工作台接入设计

## 目标与已选路线

用户于 2026-10-30 选择路线 A：复用 YanagionSabigi/review-workbench 本体，通过 AiNiee 适配器接入术语表校对和微信读书反馈校对。人在网页选择、编辑、留言并提交本轮，回到聊天说继续后，agent 比较当前稿并调用业务写回。保存草稿不构成提交。

另一路线 B 是只修改静态 HTML 的外观，保留聊天逐项批复；其改动较小，但需要重复开发工作台已有的交互，用户未选。

本次为现有技能的一项完整功能改造。保持翻译、解析、PDF 出版和最终交付流程；旧阅读报告与聊天编号批复继续可用。所有开发、Git、书籍材料、截图与验收资料保存在当前工作区；不 push，不创建 PR，不部署。完成后更新本机已安装的 ainiee-translate，更新前在工作区保存备份。

## 用户流程

### 术语表

agent 准备已锁定词表及可选建议词表。工作台按人物、术语、禁翻项分组，显示原词、当前译名、建议、分类、别名及说明；有上下文时提供原文依据。无建议显示 proposal=null，不能生成假建议。已有词条逐项校对，首版不在网页新增或删除实体。

接受、保留、手动修改形成完整最终内容；留言进入待 agent 处理队列。提交后比较最新词表：相同内容记为已满足；基准未变化可应用；本条已被外部修改则显示冲突。写回只更新对应字段，保留词条未知字段与词表其他部分，校验结构及项目 JSON Schema。锁内核验、备份、原子写入；重复执行不重复应用。

### 微信读书反馈

沿用 freeze → sync/import-notes → match/resolve → tasks/assess。使用固定 report_revision 的不可变 JSON 建审核包，不用最新建议替换用户看过的建议。每项保持完整 WR 编号、annotation_revision、assessment_revision、edition_id 与业务身份。

默认左栏为评估时现译 A，右栏为确切推荐全文。evidence 提供英文原文、冻结阅读选区、全部用户想法、存在的 A/B/C 候选、推荐理由、不确定项及 PDF 页码；有已核验的本地原页图时可提供图片证据，不重新声称已审阅原页。正文每段是独立 block，block 与 segment_id 的映射固定保存，手动编辑跨段时不能猜换行边界。

接受使用本包推荐，保留使用 A，其他候选可在手动编辑中选用完整文本或由 agent 按用户明确指令处理；首版复用原工作台的四种处理方式，不增加另一套候选提交协议。留言（例如“用 B”或进一步问题）作为待 agent 处理指示，不能自动当作批准文本。无辨析、待定位、待关联的条目仍可查看并留言，但修改译文须先补全业务定位和辨析，不能绕过原闸门。

网页正式提交是人工决定的证据，聊天“继续”授权 agent 消费已提交记录。适配器把 accept/keep/edit 转成 reading-decisions/1，human_reference 指向具体 submission 文件；保留网页动作和完整决定，不虚构聊天逐条批准。继续使用 record_decisions 和 apply_decisions 的锁内 CAS、版本拒绝、事务恢复与撤回机制；不直接改 cache。评论留待 agent 辨析，不关闭未解决的问题。整本已读完和 finalize 沿用原要求，提交一轮不代表全书完成。

## 架构与接口

新增 `python -m ainiee_translate.workbench`，提供：

- `glossary --locked PATH [--proposals PATH] --out NEW_PROJECT`：生成并冻结审核项目。
- `reading --round ROUND --cache CACHE --out NEW_PROJECT`：由最新或显式指定报告建立冻结审核项目。
- `serve PROJECT [--port N] [--no-open]`：复用工作台的本机服务，输出完整 URL。
- `compare PROJECT [--cache CACHE | --locked PATH]`：投影真实业务当前稿，调用工作台比较，展示可应用、已满足、冲突及需 agent 处理项。
- `apply PROJECT [--cache CACHE | --locked PATH] --instruction-file PATH`：只消费有效已提交决定，指令文件含真实 human_instruction 与 human_reference；返回逐项结果，非零退出码表示仍有冲突。该命令本身由 agent 在用户说继续后调用，网页服务不写业务稿。

精确参数名称可由实现者根据代码自然命名，但上列用户能力均需可调用。业务层分为共享 runtime/材料桥接、词表适配器、阅读适配器；每个模块保持单一责任。

固定上游提交 `1b800d28025846edffc404402e08ebb7ba95a90f`，随技能附带 Python 包、schemas、web 和离线 KaTeX/字体以及许可证，不在用户运行时下载、不依赖外部工作台安装。记录来源与本地补丁。使用现有 Python 3.12 环境；工作台需要的 jsonschema 纳入明确依赖，纯文本校对无需 Node，公式决定沿用上游 Node 要求。

每个 NEW_PROJECT 位于用户明确工作区内，建立独立本地 Git，不将真实书籍加入开发仓库历史。只冻结规范化审核材料、映射清单及明确资源，原书/真实 cache 保持业务路径，不复制整项目。包内保存业务映射和材料哈希并纳入冻结范围；消费时核对 Git 基准、包指纹和映射，拒绝替换或跨包使用。包 ID、条目与目标稳定，重复源词通过路径/分组/索引定位，索引漂移或身份不符拒绝写回。

同一业务段被多个 issue 覆盖时，同 target_id 的最终决定由工作台统一比较；不同决定保留冲突，不能按文件顺序覆盖。跨段 issue 使用固定有序 block 映射，部分失败如实汇报。已消费提交留有映射记录，重跑复用对应 decision_id；崩溃恢复继续由既有事务闸门负责。发现新修订后开启新包，保留旧包。

## 界面与 Refactoring UI 约束

检测结果：原生 HTML/CSS/JS；没有 Tailwind、组件库；上游已有 CSS variables，只有浅色主题。沿用 `--paper`、`--surface`、`--ink`、`--muted`、`--action` 等变量，以及 UI 14px、正文 18px、4/8/12/16/24/32/48px 间距和 8px 圆角；不新增构建工具。

主要内容是当前项的译文对照及人工决定；其次是阅读想法、建议理由与原文；版本与技术审计为第三级，默认收起。保留可折叠目录和条目队列、单项/连续阅读、搜索筛选。全页主操作为“提交本轮”，其余为次级或文字按钮。正文阅读宽度控制在适合长段落的范围内，桌面双栏，375px 单栏；用文字、图标和差异标记辅助颜色，键盘焦点清晰。

以真实《氧气》数据检查长段落、8 条手机反馈和 1 条扩展发现；术语表如真实词表为空则用独立合成小词表补充交互测试，并明确标记。截图和报告保存在忽略的 local 下。界面验证必须实际打开并查看 1280px 与 375px 截图，按层级、间距、文字、颜色、深度顺序检查。

## 验收

1. 正常创建两类审核包、启动、编辑、保存、重新打开、提交、比较可运行；打包后从中立目录也可用。
2. 回归覆盖：草稿不消费；跨段编辑不串段；已变化业务稿拒绝覆盖；旧报告/笔记/评估拒绝；留言不变成批准；重复提交及重复 apply 幂等；同目标不同决定保留冲突；冻结映射篡改拒绝；中文、emoji、HTML 文字不被当作指令或执行。
3. 词表保留未知字段、禁翻标记和别名，项目 Schema 校验失败不落盘；写回有备份且原子化。
4. 《氧气》工作副本完成真实材料导入和界面验证；未经本轮逐项人工选择，不对真实原项目套用测试决定。自动写回测试使用隔离副本/合成夹具，记录真实与合成证据的区别。
5. 相关测试、打包漂移检查通过；技能入口与说明更新，明确网页正式提交和聊天继续的职责。本机安装更新后验证命令入口可用。

模块具体分拆、CLI 输出组织、局部 UI 微调、测试夹具与备份格式由实现者决定，并在提交与验收中记录。不存在需要用户选择的新产品方向。后续扩大到表格/公式翻译的业务写回不属于本轮。
