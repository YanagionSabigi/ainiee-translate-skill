# 两种常用校对场景与 Workbench 0.3.0

## 目的与已确认需求

以最新 Review Workbench 0.3.0 为基础，保留满意的微信读书反馈校对方式，重新整理扫描术语表的初审。减少重复信息，让人仅看目录即可初步检查译名，并能按派生关系批量审核。

用户于 2026-11-01 确认：「同意一类」一次批准组内派生词各自显示的暂定译名，仍能逐项修改。顶部预览与目录子项上排原词，下排当前暂定译名；无译名则不显示第二行。其余接受前轮描述。

## 上游与范围

已读取指定仓库 v0.3.0，标签和 HEAD 均为 `3ada76923a62b28cd7a3c5e47dcd423b5f5cf82d`。同步其导航、状态样式、整页批准及相关修复；保留 AiNiee 的字段校验、业务映射、私有临时目录、精简导出和微信读书显示补丁。协议 schema_version 仍为 1，本地新增可选展示字段并严格校验；不声称这些字段是上游协议。

仅本地开发，不推送、不发布、不创建 PR，不修改已安装 skill。代码、Git 与验收材料全部留在本工作区。设计和实现使用新分支 `feat/workbench-030-review-presets`。

## 方案

采用「同步通用运行时，业务适配层准备两种展示场景」。继续共用保存、提交、比较、回写与导出机制，不复制出第二套工作台。

曾考虑只换标题和隐藏字段，但不能表达派生关系或限制批量范围；也考虑单独建立术语前端，但会重复维护提交与回传。因此推荐共用运行时、显式场景与派生关系。用户已接受前轮方向。

## 微信读书反馈

保留阅读选区和阅读想法独立展示，桌面并列、窄屏上下排列；保留显示断行整理和引用到原始偏移的映射。正文继续比较现译与冻结推荐，原文、候选和核验依据可展开。接入 0.3.0 的前后导航、状态色及侧栏；不把术语专用目录和批量规则应用于微信读书。

## 术语详情

「术语信息」默认展开，按顺序显示原词、分类领域、一句真实原文上下文和 PDF 物理页码（从 1 开始）。缺数据不编造，字段值可留空，并标为必审；旧说明中的页码列表不能冒充某句上下文的精确页码。

左侧「当前译名」只显示当前译名；右侧「建议译名」只显示真实建议修改或 AI 准备的有力备选。没有建议时不制造备选。去掉重复的 src、分类/说明比较块、固定修改依据提示和底部重复原词折叠栏。保留必要的审核操作、状态和错误反馈。

此场景的术语决定只编辑 dst；category、note、keep_source 和未知字段保持原值。人物与禁翻项保留既有字段审核能力。旧冻结包沿用旧绑定和字段集合，不原地改写历史。

## 材料与派生关系

由 AI 在准备审核材料时按语义明确标注派生关系，不通过字符串包含自动推断。例如 financial account、household account 属于 account 派生词；free module、projective module 属于 module 派生词。基础词独立保留，派生词不再与它并列为普通基础词。

实现者采用独立、可选的审核信息 JSON 输入（拟用 `--review-data`），按原词关联领域、上下文、物理页码及基础词。这样不要求改写现有 locked 词表，也不把业务来源藏在 note 中。校验原词唯一性、未知关联、基础词存在性、循环及上下文/页码类型；有歧义直接报错。AI 准备指南必须说明对照真实 PDF 填写证据，派生关系不确定时交人审核。未提供新元数据的旧词表仍能打开，无证据的字段为空且必审，不能批量越过。

具体 JSON 键名、内部展示字段和辅助模块划分由实现者决定，并记录协议、例子及测试。

## 目录与顶部预览

侧栏普通术语为「术语」目录的次级子项；派生词在相应基础词的派生类目下分组。基础词自身保持独立可审，不因批量批准派生词而被顺带批准。各项均可直接点击定位。

普通术语不显示顶部条目网格和其批量按钮。仅在浏览某一派生类时显示该类顶部预览和「同意一类」，绝不混入其他类或普通术语。顶部预览和侧栏子项都使用同一两行显示：原词在上、当前暂定译名在下。默认译名来自 before；用户明确选择建议或手动编辑后，展示其当前决定中的译名，未选择的 proposal 不抢占预览。无译名不显示第二行。

## 同意一类

作用于当前明确派生类的完整集合，不受分页截断；筛选不悄悄扩大批量范围。为尚未处理、非必审且有暂定译名的项目记录 keep 决定，精确保留左侧当前暂定译名，不自动采用右侧备选。不覆盖已有人工草稿、编辑、意见或已提交决定；这些项目仍可单独打开修改。按钮使用「同意一类」，避免与上游「全选批准本页」混淆。

批量操作仍先保存草稿，由人点击「提交本轮」形成正式决定；agent 不代填、不代提交。缺上下文、页码、无法确定关系或没有译名的项目不可由批量操作略过必审。

## 回写与兼容

每个派生词仍有独立稳定 item_id、target_id 和最终 blocks。分组仅服务导航及批量选择，不把整类拼成一个业务目标。沿用正式提交、当前稿比较、身份核验、冲突保护、备份及原子写回。旧包不自动刷新；新界面通过新建/重新导出审核包交付。

## 验收

使用公开合成材料，覆盖 account/module 两个派生类、普通术语、缺译名/缺证据项和中文长词；不把私人书籍或笔记纳入代码历史。

- 验证四项术语信息、默认展开、两侧仅译名、无冗余说明及重复原词。
- 验证普通术语仅在目录子项，派生预览仅当前类，所有预览上原词下译名，选择和编辑后同步更新。
- 跨页批量仅保留当前类暂定译名，存在备选也不自动采用；跳过必审、人工草稿和提交项目；单项仍能编辑。
- 实际提交、导出、导入、比较、回写，确认派生词独立决定及其他词表字段完整保留；旧包继续兼容。
- 微信反馈断行、引用偏移、段落编辑和既有业务回写回归；0.3.0 快捷键不干扰输入框/对话框。
- 桌面与窄屏检查目录、两行词条和译名比较，检查技能包/精简导出携带新增资源。运行相关 Python/Node 测试与全量回归，验收结果存本地。
