## 方案比较

1. **通用契约＋按 module 提供分类和姓名政策（用户选择）。** 三类核心词条共用稳定身份、语言、别名和引用；分类内容独立于契约，可以为空。兼容层集中解决旧流程接入。
2. **直接采用数学专用契约。** 可复用数学家与数学对象的命名，但会把所有翻译任务限制到数学语境，且附带用户不需要的领域内容。
3. **仅给旧表增加自由文本说明。** 改动较小，但无法可靠区分缩写义项、多语言姓名表示、分类关系及稳定引用。

本次不收录数学对象专用集合、数学对象类型枚举、完整数学词库或已有数据迁移脚本。将来需要专门对象时另行扩展契约。

## 默认数据契约

新建 module 的 `glossary.locked.json` 使用独立的 Draft 2020-12 Schema。保留单份正式词表；运行时兼容视图只在内存中生成，不另存第二份可编辑的正式表。

根对象包含 `schema_version: "1.0.0"`、`taxonomy_version: "1.0.0"`、`categories`、`persons`、`terminology`、`abbreviations`、`non_translate`，以及按需使用的 `policy_sha256`。新建时所有集合为空。Schema 版本与分类内容版本分开；版本号不意味着已经提供分类内容。

### 语言形式与共同字段

- 语言形式使用 `{text, language}`，语言记录实际语言及需要的文字标签，例如 `fr`、`ru-Latn`、`und`；文字保留 Unicode 和重音符。
- 三类条目都有稳定 `id`、必填 `source_form`，以及按需填写的 `category_ids`、`aliases`、`derived_forms`、`references`、`note`。
- ID 分别使用 `person.*`、`term.*`、`abbr.*`，全表唯一。显示写法或分类移动不改变 ID。同形异义分别建项，并填写辨义说明；不按同姓或字符串前缀自动合并。
- 别名带语言和 `usage: accepted | recognition_only`；二者都可识别，后者不作为推荐译名。词形带语言和 `kind`。独立含义的派生另建条目，通过引用关联。
- 术语和缩写的首选译文使用 `target_form: {text, language}`，支持现有非中文翻译方向，不强制都叫中文译名；未确认译文允许暂缺，必须报告待审核，不能伪造。
- 所有字段采用明确的结构约束，未知字段不在新契约中静默通过；旧格式仍按旧规则读取并保留未知字段。

### 人名 persons

保存 `source_form`、`latin_form`、`chinese_translation` 三种表示。`source_form` 必填；缺少已确认的拉丁转写或汉字名时省略相应可选字段，校验与输出报告缺失，不用音译猜造数据。三种表示必须指向同一人物且姓名范围一致。

另设可选 `name_system: han | latin | other | unknown`，描述经确认的人物姓名体系，供默认 D 模式使用。它不是国籍，不由输入字符串是否含英文字母推断。`chinese_translation` 保存经确认的汉字姓名，包括日本姓名的原有日语汉字。

姓名不需要性别或称呼作为结构字段。既有小说角色的性别等信息继续在旧格式中保留；本次不强制转换。

### 术语 terminology

一个概念对应一个稳定条目，包含源语、首选目标译文、别名、必要词形及引用。分类可关联多个 ID。可选 `tex` 只保存排版表示，不把数学模式符号混入普通识别文本。本次不实现通用 TeX 参数模板引擎。

包含人名的固定表达可用可选 `target_template` 显式引用 `person.*`，例如 `<<person:person.poincare>> 猜想`；引用必须存在并出现在 `references` 中。模板仅替换明确的人名占位符，不按字符串包含关系猜测冠名，不修改数学变量。没有模板的已有固定译文按原值使用，并在 Markdown 中说明需人工检查与人名政策一致。

`target_template` 与 `target_form` **互斥**，以避免两个权威目标。有模板时模板本身是正式值，工作台编辑实际模板文本并显示当前模式的只读展开预览，绝不能把预览写入 `target_form`。二者都没有时只能是待审核候选；不能作为已确认译名。

### 文字缩写 abbreviations

每个缩写义项独立建项，必填 `expansion: {text, language}`。采用 `target_form` 保存约定译法，也可通过明确的 `keep_source: true` 保留缩写；不默认把所有缩写机械展开。

通用写作缩写可标记 `common: true`；专门缩写可关联分类，但不强制先有分类才允许建项。默认空表不附带任何预置缩写。同形多义保留候选，使用上下文和明确选择决定义项，运行时视图不能用字典覆盖其中一个。

本次不新增逐处义项选择数据库。识别形式命中多个身份时，扫描／verify 返回带候选 ID 的“待辨义”问题，不要求译文同时含有所有候选译名；即使其中某个目标出现，也不宣称已唯一核验。此原则同样适用于同姓人名。已经通过稳定 ID 明确关联的引用／模板可直接解析，不再当作字符串歧义。Markdown 指导 Agent 根据上下文作语义核对，未解决的机械检查保留为待审核。

### 禁翻项 non_translate

保留既有 `marker`、可选 `category`、`regex`、`note` 的意义，与文字缩写分开。正则和结构标记不得误当作普通文字缩写。

## 领域分类：只定义结构，不给定内容

分类与词表共同携带，便于单文件校验和复制。`categories` 中每项是稳定 `id`、显示 `name`，可带 `parent_id` 与别名；深度不固定、每个节点至多一个父节点。分类 ID 不要求包含学科英文名。

- 空分类合法，不生成占位领域，不把“其他”偷偷作为默认分类。
- 条目未分类时省略 `category_ids`，lint 给出建议性提示；不会因为没有分类而禁止创建 module 或使用未分类条目。
- 非空分类 ID 必须存在；校验重复 ID、不存在的父节点、自环与父链循环。修改名称或层级保留节点身份，并维护 `taxonomy_version`。
- module 的可选分类选择使用 ID，选择父节点包含后代；默认选择全部。用户指定不存在的 ID 时明确报错。
- 按领域生成子表时包含无分类条目和 `common: true` 缩写，递归补齐跨条目引用并去重；不能丢掉未分类待整理项或引用的人名。
- 可选地从用户提供的分类 JSON 导入结构；不提供生成分类的内置枚举或自动分类命令。

Markdown 中明确建议：创建 module 或整理术语表前，先按文献内容和翻译任务生成、检查领域分类，确认名称和层级后再分配条目；这是建议，不是额外批准关卡。说明应覆盖创建 module、术语整理入口和 Schema 参考文档。

## 四种人名输出政策

政策属于 module／任务配置，不是人物词条内容。新 module 默认 D，旧 module 不因加载而改变其既有 render。

| 模式 | 输出 |
| --- | --- |
| A：完全汉化 | `chinese_translation` |
| B：拉丁文转写 | `latin_form.text` |
| C：保留源语言 | `source_form.text` |
| D：按姓名体系处理，默认 | `han` 用经确认汉字名；`latin` 保留源语言拼写；`other` 用通行拉丁转写 |

缺少选定模式所需表示，或 D 的姓名体系未确认时，暂留源文并返回明确的待核实问题。不能默默猜转写、改重音、根据国籍选汉字名；fallback 不算“姓名政策已全部核验”。政策同样用于显式人名模板。

## module 与既有流程的接入

1. 新 `module create` 默认生成新空表和任务政策快照，`module.json` 记录词表格式并引用该政策文件，政策中保存 `person_name_mode: D` 和可选分类选择。CLI 可明确选择 A/B/C/D，可导入用户提供的分类结构、保存分类选择；缺省没有领域参数。
2. `module show/list` 展示词表格式、三类计数、分类计数及姓名模式。重复创建已存在的 module 不覆写其内容或模式；参数冲突应报错，不能声称已修改。
3. `module load --work` 复制词表、提示词和政策快照，在项目 `active_module.json` 中记录来源与快照哈希，姓名模式和分类选择仅以项目快照为准。项目加载后不跟随全局 active module 变化；重新加载才显式更新并备份旧文件。
4. 新增集中式读取与兼容视图：文档读取器返回经过校验的原始数据；运行时读取器使用词表对应的政策快照，返回现有 `characters/terms/non_translate` 视图及问题列表。扫描、verify、review、precedents 等统一通过它读取，禁止各自猜字段。
5. 视图从人名得到 canonical/aliases/render，从术语和缩写得到 src/dst；保留大小写、多义候选和识别别名，不把空译文当成已审核“保留源文”。过滤和写入命令使用原始文档，不把兼容视图覆盖回正式文件。
6. verify 对新格式按“源文识别形式 → 选定模式的目标名”检查，不能继续要求每个源语别名在译文中原样出现；旧格式保持原有接口与行为。
7. `glossary lint/filter/merge-newterms` 识别两种格式。新条目作为未确认候选保留源文与待审核状态，不暗中编造译名。过滤保留新契约、分类和引用闭包。
8. profile 导入及历史模块继续使用旧格式，不自动迁移、不新增强制领域。后续需要迁移时须展示丢失信息和候选映射，另行实施。

### 政策快照的复制与校验

政策独立于词条 Schema，采用配套文件 `<词表文件的 stem>.policy.json`，例如 `glossary.locked.policy.json`。文件含其自身版本、姓名模式和分类选择，不保存分类树或词条副本。新 module 的 `module.json` 指向该文件，不再另存一份模式配置；`active_module.json` 只记录来源及哈希，不提供另一权威模式。

module 创建／加载以及 `glossary filter --out` 都携带政策文件，并在正式词表的 `policy_sha256` 中绑定配套文件的字节哈希。过滤到其他目录或改名时，按输出文件名生成配套快照并重新绑定；A/B/C 模式不得变为 D。复制／移动已绑定词表必须同时携带配套文件。绑定存在而快照缺失、哈希不符、配置非法时明确报错，不回退默认 D。独立起草且从未绑定的空表可以没有快照，此时按 D 读取。

配套文件与词表替换前都先校验；覆盖时备份两者。写入中断产生的不一致须能被哈希检查发现并从备份恢复，不能把双文件写入声称为单文件原子事务。工作台绑定政策哈希，政策变化后必须重新准备审核。

## 工作台与写回

新表在工作台分组显示人名、术语、缩写、禁翻项，通过稳定 ID 绑定。可编辑目标译名、已有姓名表示和必要说明；有模板时按上文编辑模板而非展开预览。语言形式、引用、分类及其他未编辑内容原样保留。派生分组仅复用明确的审核关系，不从词形或引用自动推断派生类。

准备审核时绑定词表身份和姓名政策；正式写回前核对当前稿与配置未冲突，通过默认 Schema 和已有可选项目 Schema，再备份和原子写入。不能把工作台对兼容视图的修改写成一张扁平旧表；不能重放旧政策下的决定覆盖新政策。

旧冻结审核包沿用已有规则，不就地升级；其未知字段、备份、草稿与正式提交的区别保持不变。人类决定仍需真实提交，本任务不代填或代提交。
