# 默认术语表设计的独立检查

日期：2026-11-06。范围：设计的可实施性、新旧词表兼容、人工审核写回与用户“不预置领域分类”的约束；不是产品实现验收。

设计：[默认术语表与翻译 module](../specs/2026-11-06-default-glossary-design.md)。

使用独立、干净上下文的审阅者，只读检查设计与 `module.py`、`glossary.py`、`verify.py`、`workbench_glossary.py`。未让审阅者执行附件脚本或修改文件。

## 第一轮发现与补正

| 发现 | 影响 | 设计中明确的决定 |
| --- | --- | --- |
| 组合模板和固定译文的权威关系不明 | 人工编辑可能不生效，或将一种模式的展开结果固化到词表 | 两者互斥；模板是正式值，工作台编辑模板、只读显示展开预览 |
| 同形多义的机械核验语义不明 | 同一处可能被要求同时出现多个译名 | 本次不新增逐处选择数据库；返回候选 ID 和待辨义问题，显式 ID 引用单独解析 |
| 过滤子表到其他目录时可能丢失 A/B/C 配置 | 姓名输出可能意外回退到 D | 配套政策快照随表复制，以哈希绑定；缺失或不符时拒绝读取；双文件写入不伪称为原子事务 |

以上属于接入方式和核验细节，由实现者提出并写入供用户批准的具体设计；没有把它们记录成用户已经确认的决定。

## 复核结果

独立审阅者重新读取补正后的设计，确认上述三项均已闭合，未发现这三项中仍存的重大矛盾。

第一轮同时确认：没有发现与“不预置领域分类、只在 Markdown 推荐提前生成分类”或保留四种人名模式相矛盾的内容；新旧格式分流、单份正式词表、冻结审核包和真实人工提交原则已有明确约束。
