# 微信读书兼容处理

用于微信读书导入，或修复脚注/角标被列入目录、文件名续项、灰底引文逐段切割。保留原文件，在独立副本上处理；原书内容审校状态保持原样。

## 处理规则

1. **目录同源。** `build` 同时生成 EPUB 3 nav 和 NCX，并在 manifest/spine 绑定 NCX。两份目录的标题、层级、顺序和目标一致，只从已审校 TOC 生成，正文脚注和返回链接保留。已有 EPUB 用 `epub_weread.py` 补齐或重建 NCX。
2. **无名续项。** 导入后若出现 `文件名_1`，先对照实际目录和源文件，判断是否为长文件自动分片。必要时用 `--split-at ZIP内路径#标题ID` 在已有 TOC 标题处显式分文件，保留完整自然段和内容顺序，更新跨文件脚注、回跳及导航。每个原文件支持一个拆点；仅支持 body 或匿名 div 内的直接标题。媒体叠加层会被拒绝，其他外部依赖另行核对。大小阈值与分片算法未经证实，不把《区判》的切点套到其他书。
3. **灰底引文。** 用户接受去底色时，使用 `--plain-callouts` 移除 div 上的 `bgc_HEX` 类，保留引文、署名、自然段、其他样式和表格底色。该选项不处理任意行内背景或其他命名的CSS。普通生成器的引文样式继续使用淡绿、仿宋和90%字号。

```powershell
python scripts/epub_weread.py "原书.epub" "兼容版.epub" --plain-callouts --split-at "EPUB/ch1.xhtml#section-two" --report "兼容处理.json"
```

只补目录时省略后两个选项。命令拒绝覆盖原书或已有输出。测试需要独立导入时可加 `--test-label`，会更改副本书名和标识；它不迁移阅读进度或笔记，遇加密/混淆资源会拒绝改标识。

## 验证与完成条件

- 对比全部正文、段落、图片与表格，核对每个原ID唯一保留、全部注释引用和返回目标，以及 nav/NCX 的标题和目标语义；分片后的注释允许合法跨文件往返。
- 运行结构检查及 EPUBCheck；用实际 ZIP 阅读器核对分片标题、窄屏引文与署名、跨片注释及返回。按本技能的独立终校要求保存绑定最终哈希的修改范围审核，原书未完成的内容审校单独保留。
- 请用户实际导入手机：确认 footnote、纯数字角标和文件名异常条目消失，抽查脚注往返、引文署名和翻页。微信读书API可辅助只读复核目录；章节文件条目与 `anchors` 合起来看，不能把文件数当全部目录数。本地阅读器通过不代替手机结果。

《区判》已实测接受“同源NCX＋两处既有标题分片＋去灰底”的组合，详见仓库诊断记录；这仅证明该书该版本的兼容修复。原创可重建示例见 [weread-compat](../../assets/template/epub/weread-compat/README.md)，示例尚需独立手机导入测试。
