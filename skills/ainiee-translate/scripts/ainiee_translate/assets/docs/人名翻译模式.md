# 人名翻译模式的选择

人名具有身份、语言和姓名体系三个层面。同一个人可能同时有源文拼写、通行拉丁转写与中文译名。把这些资料分开保存，再由任务选择正文形式，可以让同一份术语表用于不同项目，避免改一次模式就覆盖译名资料。

| 模式 | 正文采用的表示 | 适合的需要 |
| --- | --- | --- |
| A：完全汉化 | 经确认的 `chinese_translation` | 中文阅读连贯，或统一采用已有中文译名。 |
| B：拉丁转写 | `latin_form.text` | 跨文字体系比较、检索和统一拉丁字母姓名。 |
| C：保留源语言 | `source_form.text` | 对照原文、保留重音和原语言拼写。 |
| D：按姓名体系（默认） | 汉字姓名用汉字；拉丁体系保留源文；其他体系用拉丁转写 | 同时照顾汉字姓名的原有写法、拉丁姓名的可检索性与其他文字的阅读便利。 |

D 不是“所有人名都不翻译”：`name_system: han` 选汉字名，`latin` 选源文，`other` 选拉丁转写。例如已确认的汉字姓名可使用原有汉字，Levi-Civita 等拉丁姓名保留实际源文。不能根据国籍、输入字符或文件语言猜测姓名体系；拉丁化的日本姓名也需要先确认身份。

默认 D 的考量是减少无依据的音译，同时保留跨语言检索线索。A、B、C 则让希望统一汉化、转写或原文的项目能明确覆盖默认选择。缺少模式需要的表示、或体系为 `unknown` 时，暂留源文并列为待核实，不能将回退当作已经确认。

在翻译模组的 `预设参数.md` 中填 A、B、C 或 D；创建时也可用 `module create <名字> --name-mode A`。加载模组会把所选政策绑定到项目词表，进行中项目不受全局激活模组改变的影响。改模式后重新加载，并复核既有译文与冠名术语；加载不会自动重译。

术语表应记录可核实的中文音译或通行译名：人名填 `chinese_translation`，一般术语填目标语言 `target_form`。即使正文采用 D 或 C，也无需在目标译名栏重复源语言。源语言已经保存在 `source_form`，拉丁转写保存在 `latin_form`。冠名组合可用引用人名的 `target_template` 随模式展开；固定中文译法可直接用 `target_form`，另在 `note` 说明约定。详见[术语表文档](术语表文档.md)。

同一姓名内用连字符，例如庞-巴维克、Levi-Civita；两位人物共同冠名用连接号，例如 Newton–Leibniz。详见[标点符号与空格](标点符号.md)。
